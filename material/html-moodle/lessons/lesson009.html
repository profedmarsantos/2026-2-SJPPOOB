Módulo 09

Modificadores de Acesso

Objetivo: usar public, private e protected corretamente para proteger dados e organizar responsabilidades.

Introdução teórica

Nem todo dado da classe deve ficar visível para qualquer parte do sistema.

Modificadores de acesso definem o que pode ser acessado de fora da classe e o que deve ficar protegido.

Conceitos essenciais desta aula

  • public: acessível por qualquer classe.
  • private: acessível apenas dentro da própria classe.
  • protected: acessível na própria classe e nas classes derivadas.

Tabela comparativa rápida

Modificador Onde pode ser acessado Uso comum
public Em qualquer classe Métodos de serviço e operações que precisam ser chamadas externamente
private Apenas na classe atual Campos internos e detalhes de implementação
protected Na classe atual e em classes filhas Dados compartilhados em hierarquias de herança

Exemplo em C#

using System;

class Pessoa
{
    public string Nome;
    private string cpf;
    protected string codigoInterno;

    public void DefinirCpf(string valor)
    {
        cpf = valor;
    }

    public string ObterCpfMascarado()
    {
        return "***.***.***-**";
    }
}

class Aluno : Pessoa
{
    public void DefinirCodigo(string codigo)
    {
        codigoInterno = codigo;
    }
}

class Program
{
    static void Main()
    {
        Aluno a = new Aluno();
        a.Nome = "Lia";
        a.DefinirCpf("12345678900");
        a.DefinirCodigo("A-2026");

        Console.WriteLine("Nome: " + a.Nome);
        Console.WriteLine("CPF: " + a.ObterCpfMascarado());
    }
}

Leitura guiada do exemplo

  1. Nome é público e pode ser lido e alterado externamente.
  2. cpf é privado, então só a própria classe Pessoa pode manipular diretamente.
  3. codigoInterno é protegido, então a classe Aluno consegue acessar.
  4. Métodos públicos funcionam como acesso seguro para dados privados.

Exercícios de fixação

  1. Exercício 1: classifique os membros abaixo em public, private ou protected: saldo, NumeroConta, agenciaInterna.

    Ver resposta

    Uma resposta esperada: saldo private, NumeroConta public, agenciaInterna protected.

    Ver resposta 
    private decimal saldo;

public void Depositar(decimal valor)
{
    if (valor > 0)
        saldo += valor;
}

  3. Exercício 3: explique por que deixar todos os atributos públicos pode causar problemas.

    Ver resposta

    Porque qualquer classe pode alterar dados sem validação, gerando estado inválido e comportamento imprevisível.

  4. Exercício 4: crie uma classe derivada que use um campo protected da classe base.

    Ver resposta

    A classe filha pode atribuir valor ao campo protected dentro de seus métodos, sem expor esse campo para qualquer classe externa.

Resumo da aula

Modificadores de acesso controlam visibilidade e ajudam a proteger o estado interno.

Escolher corretamente entre public, private e protected faz parte da boa modelagem orientada a objetos.

Atividade guiada

Passo 2: adicione método público para depósito com validação.

Passo 3: crie classe ContaAluno herdando de Conta e utilize um campo protegido na classe base.
