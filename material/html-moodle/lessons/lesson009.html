Módulo 09

Modificadores de Acesso

Objetivo: usar public, private e protected corretamente para proteger dados e organizar responsabilidades.

1. Introdução teórica

Nem todo dado da classe deve ficar visível para qualquer parte do sistema.

Modificadores de acesso definem o que pode ser acessado de fora da classe e o que deve ficar protegido.

2. Conceitos essenciais desta aula

Os modificadores de acesso definem quem pode ver e usar um membro da classe. A ideia principal é controlar o que é público para o sistema e o que fica interno à classe.

  • public: o membro fica visível para qualquer classe do programa. É como dizer: “qualquer parte do sistema pode usar isso”.
    • Use quando a informação ou operação precisa ser acessada de fora da classe.
    • Exemplo: um método que realiza uma ação útil para outras classes.
  • private: o membro só pode ser usado dentro da própria classe. Nenhuma outra classe consegue acessar diretamente.
    • Use para guardar dados internos e proteger regras da implementação.
    • Exemplo: um atributo que representa um valor sensível, como saldo, CPF ou código interno.
  • protected: o membro pode ser usado na própria classe e também nas classes derivadas, ou seja, nas classes filhas.
    • Use quando a classe base quer compartilhar algo com as classes filhas, sem expor esse membro para todo o sistema.
    • Exemplo: um campo que a classe filha precisa herdar e reutilizar.

Diferença prática:

  • public = “todo mundo pode ver e usar”.
  • private = “só a própria classe pode usar”.
  • protected = “a própria classe e as classes filhas podem usar”.

3. Tabela comparativa rápida

Modificador Onde pode ser acessado Uso comum
public Em qualquer classe Métodos de serviço e operações que precisam ser chamadas externamente
private Apenas na classe atual Campos internos e detalhes de implementação
protected Na classe atual e em classes filhas Dados compartilhados em hierarquias de herança

4. Exemplo em C#

Arquivo 1: Pessoa.cs

using System;

public class Pessoa
{
    public string Nome;
    private string cpf;
    protected string codigoInterno;

    public void DefinirCpf(string valor)
    {
        cpf = valor;
    }

    public string ObterCpfMascarado()
    {
        return "***.***.***-**";
    }
}

Arquivo 2: Aluno.cs

using System;

public class Aluno : Pessoa
{
    public void DefinirCodigo(string codigo)
    {
        codigoInterno = codigo;
    }
}

Arquivo 3: Program.cs

using System;

class Program
{
    static void Main()
    {
        Aluno a = new Aluno();
        a.Nome = "Lia";
        a.DefinirCpf("12345678900");
        a.DefinirCodigo("A-2026");

        Console.WriteLine("Nome: " + a.Nome);
        Console.WriteLine("CPF: " + a.ObterCpfMascarado());
    }
}

5. Leitura guiada do exemplo

  1. Nome é público e pode ser lido e alterado externamente.
  2. cpf é privado, então só a própria classe Pessoa pode manipular diretamente.
  3. codigoInterno é protegido, então a classe Aluno consegue acessar.
  4. Métodos públicos funcionam como acesso seguro para dados privados.

7. Resumo da aula

Modificadores de acesso controlam visibilidade e ajudam a proteger o estado interno.

Escolher corretamente entre public, private e protected faz parte da boa modelagem orientada a objetos.

8. Atividade guiada

Passo 1: crie a classe Conta com campo saldo privado.

Passo 2: adicione método público para depósito com validação.

Passo 3: crie classe ContaAluno herdando de Conta e utilize um campo protegido na classe base.
