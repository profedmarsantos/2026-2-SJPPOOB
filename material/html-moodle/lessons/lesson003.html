Módulo 03

Classe e Objeto

Objetivo: compreender a relação entre classe e objeto e aplicar atributos e métodos em instâncias diferentes.

1. Classe e objeto na prática

A classe define o modelo. O objeto é a instância criada a partir desse modelo.

Cada objeto guarda seus próprios dados e executa ações por meio de métodos.

2. Conceitos essenciais desta aula

Atributo

Armazena informações do objeto, como nome, idade, saldo ou preço.

Método

Representa uma ação que o objeto pode executar, como mostrar dados ou calcular um valor.

Estado

É o conjunto de valores atuais armazenados nos atributos do objeto.

Comportamento

É a forma como o objeto reage quando um método é chamado.

Resumo: a classe define o modelo; os atributos guardam os dados; os métodos representam as ações; cada objeto possui seu próprio estado.

3. Exemplo com atributo e método

Vamos usar a classe Conta com um titular, um saldo privado e métodos para mostrar e depositar valores.

Arquivo 1: Conta.cs

using System;

public class Conta
{
    public string Titular = "";
    decimal Saldo = 0;

    public void MostrarSaldo()
    {
      Console.WriteLine();
      Console.WriteLine($"Titular: {Titular}");
      Console.WriteLine($"Conta Saldo: {Saldo}");
    }

    public void Depositar(decimal valor)
    {
      Saldo += valor;
    }

}

Arquivo 2: Program.cs

using System;

class Program
{
    static void Main()
    {
        Conta a = new Conta();
        a.Titular = "Fulano Silva";
        a.MostrarSaldo();
        a.Depositar(500);
        a.MostrarSaldo();
    }
}

Neste exemplo, o objeto a tem seus próprios dados e executa ações por meio dos métodos da classe.

4. Por que o atributo saldo deve ser private?

O atributo saldo representa um dado interno da conta. Ele deve ser private para impedir alterações diretas fora da classe.

Se saldo fosse público, qualquer parte do programa poderia atribuir um valor negativo diretamente, sem verificar se o valor é válido.

Com o atributo privado, a classe controla as alterações por meio dos métodos Depositar e Sacar. Assim, as regras ficam concentradas na classe e o estado do objeto permanece válido.

No arquivo atual, Saldo não tem um modificador escrito. Em um campo de classe, isso significa que ele é privado por padrão. Escrever private explicitamente também documenta essa decisão.

private decimal Saldo = 0;

public void Depositar(decimal valor)
{
    Saldo += valor;
}

O programa consulta e altera o saldo por métodos públicos, sem acessar o campo diretamente.

5. Exemplo completo atualizado

O código abaixo corresponde à implementação atual dos arquivos Conta.cs e Program.cs.

Arquivo 1: Conta.cs

using System;
using System.Runtime.CompilerServices;

class Conta
{
    public string Titular = "";
    decimal Saldo = 0;

    public void MostrarSaldo()
    {
        Console.WriteLine();
        Console.WriteLine($"Titular: {Titular}");
        Console.WriteLine($"Conta Saldo: {Saldo}");
    }

    public void Depositar(decimal valor)
    {
        Saldo += valor;
    }
    
    public void Sacar(decimal valor)
    {
        if (valor <= 0)
        {
            Console.WriteLine();
            Console.WriteLine("Valor inválido. O valor deve ser maior que 0 (zero).");
        }
        else if (valor > Saldo)
        {
            Console.WriteLine();
            Console.WriteLine("Valor inválido. O valor deve ser menor ou igual ao saldo atual.");
        }
        else
        {
            Saldo -= valor;
            Console.WriteLine();
            Console.WriteLine($"O valor {valor} foi sacado com sucesso!");
        }
    }
}

Arquivo 2: Program.cs

using System;

class Program
{
    static void Main()
    {
        Conta a = new Conta();
        a.Titular = "Fulano Silva";
        a.MostrarSaldo();
        a.Depositar(500);
        a.MostrarSaldo();
        a.Sacar(75);
        a.MostrarSaldo();
    }
}

O Main usa os métodos públicos da classe. O campo Saldo continua protegido contra acesso direto.

6. Outro exemplo: cláusula de guarda profissional

A implementação atual usa if/else e mensagens no console. Como alternativa, uma versão mais profissional pode retornar true ou false e usar cláusulas de guarda.

Esse estilo testa cada condição no início do método e retorna imediatamente quando encontra um problema. O exemplo abaixo é uma alternativa; ele não substitui os métodos dos arquivos atuais.

// ESTILO CLÁUSULA DE GUARDA: Limpo, reto e direto
  public bool SacarComGuarda(decimal valor)
  {
    if (valor <= 0) return false;          // Barreira 1
    if (valor > saldo) return false;       // Barreira 2
    if (!ContaAtiva) return false;         // Barreira 3
    if (valor > LimiteDiario) return false; // Barreira 4

    // Se chegou aqui, é porque passou por todos os testes!
    saldo -= valor;
    return true;
  }
  1. Barreira 1: impede saque zero ou negativo.
  2. Barreira 2: impede saque maior que o saldo disponível.
  3. Barreira 3: impede operação em conta inativa.
  4. Barreira 4: impede saque acima do limite diário.

7. Leitura guiada do exemplo

  1. Classe Conta: define o titular, o campo privado Saldo e os métodos da conta.
  2. Método MostrarSaldo: mostra o titular e o saldo atual no console.
  3. Método Depositar: adiciona o valor recebido ao saldo.
  4. Método Sacar: valida o valor, verifica o saldo e realiza o saque quando possível.
  5. Objeto a: é criado com new Conta() e recebe o titular "Fulano Silva".

Esse fluxo mostra a ideia central da aula: a classe define o modelo e o objeto guarda o estado real durante a execução.

8. Diferença entre atributo e método

O atributo guarda informação. O método executa uma ação.

Em uma classe Aluno, o atributo Nome guarda o nome do aluno. O método Apresentar mostra esse nome na tela.

Assim, a classe une dados e comportamento em um único modelo.

9. Vários objetos, valores diferentes

Cada objeto pode ter valores diferentes para os mesmos atributos. Isso é um ponto importante da POO.

Conta c1 = new Conta();
Conta c2 = new Conta();

c1.Titular = "Ana";
c1.Depositar(100);

c2.Titular = "Bruno";
c2.Depositar(300);

Mesmo usando a mesma classe, os objetos c1 e c2 possuem estados diferentes.

10. Erros comuns nesta etapa

  • Esquecer de criar o objeto: tentar usar atributos e métodos sem executar new.
  • Confundir classe com objeto: tratar o nome da classe como se já fosse uma instância.
  • Não alterar o estado: chamar método sem atualizar os dados necessários.
  • Duplicar lógica no Main: colocar regras de negócio fora da classe em vez de usar métodos.

12. Resumo da Aula

A classe organiza dados e ações. Os atributos guardam o estado do objeto, enquanto os métodos definem o comportamento.

Isso torna o código mais claro, mais organizado e mais próximo de situações reais.
