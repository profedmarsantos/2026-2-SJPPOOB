Módulo 19

Distribuicao do Aplicativo

Objetivo: preparar e entregar a aplicacao para execucao em outros computadores com menos risco de erro.

Introducao teorica

Distribuir uma aplicacao significa gerar os arquivos corretos para o ambiente de uso.

Nessa etapa, o foco e transformar o projeto de desenvolvimento em pacote executavel.

Conceitos essenciais desta aula

  • Build: compilacao do codigo para gerar binarios.
  • Publish: pacote pronto para distribuicao.
  • Release: configuracao otimizada para entrega final.
  • Dependencias: arquivos e bibliotecas necessarios para executar.

Exemplo de comando

dotnet publish -c Release -r win-x64 --self-contained false

Esse comando gera os arquivos de publicacao para Windows 64 bits usando runtime instalado no destino.

Checklist de distribuicao

  1. Compilar sem erros em modo Release.
  2. Executar testes basicos do fluxo principal.
  3. Gerar pacote com dotnet publish.
  4. Validar se arquivos de configuracao foram incluidos.
  5. Testar em maquina ou pasta limpa.

Exercicios de fixacao

  1. Exercicio 1: explique a diferenca entre build e publish.

    Ver resposta

    Build compila o projeto. Publish gera o pacote final de entrega.

  2. Exercicio 2: escreva um comando publish para Linux x64.

    Ver resposta 
    dotnet publish -c Release -r linux-x64 --self-contained false

  3. Exercicio 3: cite dois riscos de distribuir sem testar o pacote.

    Ver resposta

    Falta de arquivos essenciais e falhas de execucao no ambiente do usuario.

  4. Exercicio 4: crie um mini-checklist de entrega para seu projeto final.

    Ver resposta

    Incluir compilacao, testes, publish, validacao de configuracao e teste final em ambiente limpo.

Resumo da aula

Distribuicao e parte tecnica essencial para colocar o sistema em uso real.

Um processo de publish com checklist reduz falhas na entrega.

Atividade guiada

Passo 1: execute build em Release no seu projeto.

Passo 2: rode o publish para o sistema operacional alvo.

Passo 3: liste os arquivos gerados na pasta de saida.

Passo 4: valide o executavel em ambiente limpo e registre resultado.
