Aula 10

Herança

Objetivo: reutilizar dados comuns de uma pessoa nas classes Aluno e Professor.

1. Objetivo e resultado esperado

Você criará uma classe base chamada Pessoa e duas classes derivadas: Aluno e Professor.

As três classes terão objetos com nome. Cada classe derivada também terá uma informação própria.

O exemplo demonstra somente a herança. Ele não usa arrays, listas, validações ou banco de dados.

2. Conceitos essenciais

  • Classe base: classe que reúne membros comuns para outras classes.
  • Classe derivada: classe que herda membros acessíveis de uma classe base.
  • Herança: recurso indicado por : depois do nome da classe derivada.
  • base(...): chamada que envia valores ao construtor da classe base.

3. Diagrama do exemplo

O diagrama é de implementação. Ele representa diretamente as classes C#, incluindo visibilidades, tipos, construtores, propriedades somente para leitura e método estático.

classDiagram class Pessoa { <<public>> +Nome: string +Pessoa(nome: string) +Apresentar() void } class Aluno { <<public>> +Curso: string +Aluno(nome: string, curso: string) } class Professor { <<public>> +Disciplina: string +Professor(nome: string, disciplina: string) } class Program { -Main() void$ } Pessoa <|-- Aluno : herda Pessoa <|-- Professor : herda Program ..> Aluno : instancia e usa Program ..> Professor : instancia e usa note for Pessoa "Nome e uma propriedade publica somente leitura." note for Aluno "Curso e uma propriedade publica somente leitura." note for Professor "Disciplina e uma propriedade publica somente leitura." note for Program "Main e private static. O simbolo $ indica membro estatico."

Como ler: + representa public e - representa private. As propriedades do diagrama possuem somente get; essa restrição está descrita nas notas.

4. Organização dos arquivos

Crie um arquivo para cada classe: Pessoa.cs, Aluno.cs e Professor.cs. Use Program.cs para executar o exemplo.

5. Etapa 1: criar a classe base Pessoa

Objetivo: guardar o nome e disponibilizar uma operação comum.

Arquivo: Pessoa.cs

using System;

public class Pessoa
{
    public string Nome { get; }

    public Pessoa(string nome)
    {
        Nome = nome;
    }

    public void Apresentar()
    {
        Console.WriteLine("Nome: " + Nome);
    }
}
  1. Crie a propriedade pública Nome.
  2. Crie o construtor Pessoa com o parâmetro nome.
  3. Atribua o parâmetro à propriedade.
  4. Crie o método Apresentar para mostrar o nome.

Verificação: um objeto Pessoa recebe um nome ao ser criado e pode executar Apresentar.

6. Etapa 2: criar a classe Aluno

Objetivo: criar uma pessoa que também possui um curso.

Arquivo: Aluno.cs

public class Aluno : Pessoa
{
    public string Curso { get; }

    public Aluno(string nome, string curso)
        : base(nome)
    {
        Curso = curso;
    }
}
  1. Escreva : Pessoa depois de Aluno.
  2. Crie a propriedade Curso.
  3. Use : base(nome) para enviar o nome ao construtor de Pessoa.
  4. Atribua o curso à propriedade da própria classe.

Verificação: um objeto Aluno possui Nome, herdado de Pessoa, e Curso, declarado em Aluno.

7. Etapa 3: criar a classe Professor

Objetivo: criar uma pessoa que também possui uma disciplina.

Arquivo: Professor.cs

public class Professor : Pessoa
{
    public string Disciplina { get; }

    public Professor(string nome, string disciplina)
        : base(nome)
    {
        Disciplina = disciplina;
    }
}
  1. Escreva : Pessoa depois de Professor.
  2. Crie a propriedade Disciplina.
  3. Use : base(nome) para inicializar o nome herdado.
  4. Atribua a disciplina à propriedade da classe.

Verificação: um objeto Professor pode acessar Nome e executar Apresentar, porque esses membros pertencem à classe base.

8. Etapa 4: usar as classes no programa

Objetivo: criar um aluno e um professor para observar os membros herdados e os membros próprios.

Arquivo: Program.cs

using System;

class Program
{
    private static void Main()
    {
        Aluno aluno = new Aluno("Lia", "Informática");
        Professor professor = new Professor("Marcos", "Programação");

        aluno.Apresentar();
        Console.WriteLine("Curso: " + aluno.Curso);

        professor.Apresentar();
        Console.WriteLine("Disciplina: " + professor.Disciplina);
    }
}

Resultado esperado:

Nome: Lia
Curso: Informática
Nome: Marcos
Disciplina: Programação

Observação: o método Apresentar foi escrito uma vez em Pessoa. As duas classes derivadas podem usá-lo.

9. Conferir cada comportamento

  • Aluno : Pessoa: indica que Aluno herda de Pessoa.
  • Professor : Pessoa: indica que Professor herda de Pessoa.
  • base(nome): chama o construtor da classe base para inicializar Nome.
  • aluno.Nome: é permitido porque a propriedade foi herdada.
  • professor.Apresentar(): é permitido porque o método foi herdado.
  • aluno.Disciplina: não é permitido, pois essa propriedade existe somente em Professor.

10. Erros comuns

  • Esquecer : Pessoa: sem essa parte, a classe não herda os membros de Pessoa.
  • Esquecer base(nome): a classe base não recebe o valor exigido pelo seu construtor.
  • Declarar Nome novamente: não repita a propriedade nas classes derivadas. Ela já existe em Pessoa.
  • Tentar usar um membro de outra classe derivada: Aluno e Professor compartilham apenas o que vem de Pessoa.

11. Atividade de conferência

  1. Crie uma nova instância de Aluno com outro nome e outro curso.
  2. Chame Apresentar para essa instância.
  3. Crie uma classe Funcionario que herde de Pessoa e tenha a propriedade Setor.
  4. Crie um objeto Funcionario em Program.cs, chame Apresentar e mostre o setor.

Critérios de conclusão

  • A classe Pessoa contém a propriedade Nome e o método Apresentar.
  • Aluno e Professor herdam de Pessoa.
  • Os construtores das classes derivadas chamam base(nome).
  • O programa usa os membros herdados e as propriedades próprias de cada objeto.

12. Resumo

  • Pessoa concentra o dado e o comportamento comuns.
  • Aluno reutiliza Nome e acrescenta Curso.
  • Professor reutiliza Nome e acrescenta Disciplina.
  • A herança evita repetir em cada classe os membros que possuem o mesmo significado.

13. Exercício de prática: urna eletrônica

Objetivo: criar uma classe Urna que cadastre candidatos em arrays, registre votos e informe os resultados solicitados. Este exercício não exige herança.

Regra de organização: crie somente Urna.cs e Program.cs. A classe Program cria a urna, faz cadastros, registra votos e mostra os retornos. A classe Urna guarda todos os dados e aplica todas as regras.

13.1. Diagrama detalhado da classe

Este é um diagrama de implementação. Os nomes, tipos, visibilidades, parâmetros e retornos devem ser mantidos como estão no diagrama.

classDiagram class Urna { -candidatoNome: string[] -candidatoNumero: int[] -candidatoVotos: int[] -contaVotosNulos: int -contaVotosBrancos: int -contaVotosValidos: int -indexCandidato: int +Urna(max_candidato: int) +CadastroCandidato(nome: string, numero: int) void +GetNumCandidatos() int[] +GetCandidato(numero: int) string +GetVotos(numero: int) int +Votar(numeroVoto: int) void }

Leitura técnica: o símbolo - indica campo private; o símbolo + indica construtor ou método public.

Relação entre os campos: os três arrays são paralelos; o índice i representa o mesmo candidato nos três arrays. O valor -1 representa voto em branco. Um número não cadastrado representa voto nulo. indexCandidato aponta para a próxima posição livre e informa a quantidade cadastrada.

13.2. Dados privados obrigatórios

  • candidatoNome: array de textos com o nome de cada candidato.
  • candidatoNumero: array de números dos candidatos.
  • candidatoVotos: array com a quantidade de votos de cada candidato.
  • contaVotosNulos: total de votos em números que não pertencem a candidatos cadastrados.
  • contaVotosBrancos: total de votos com o número -1.
  • contaVotosValidos: total de votos destinados a candidatos cadastrados.
  • indexCandidato: quantidade atual de candidatos cadastrados e índice da próxima posição livre.

Regra dos arrays: os três arrays são paralelos. Por exemplo, os valores da posição 0 nos três arrays descrevem o mesmo candidato.

13.3. Passo a passo de implementação

  1. Construtor Urna: receba max_candidato. Crie os três arrays com esse tamanho. Inicie os três contadores de votos e indexCandidato com zero.
  2. CadastroCandidato: receba nome e numero. Cadastre somente quando indexCandidato for menor que o tamanho do array. Grave nome e número na mesma posição, mantenha os votos dessa posição em zero e avance indexCandidato. Quando não houver posição livre, não altere nenhum array nem contador.
  3. GetNumCandidatos: crie um novo array de inteiros com tamanho igual a indexCandidato. Copie para ele somente os números das posições cadastradas. Retorne esse novo array; não retorne o array privado.
  4. GetCandidato: quando receber -1, retorne exatamente VOTO EM BRANCO. Para outro número, percorra apenas as posições menores que indexCandidato. Se encontrar o número, retorne o nome correspondente. Se não encontrar, retorne exatamente VOTO NULO.
  5. GetVotos: quando receber -1, retorne contaVotosBrancos. Para outro número cadastrado, retorne a posição correspondente de candidatoVotos. Para número não cadastrado, retorne contaVotosNulos.
  6. Votar: quando receber -1, aumente somente contaVotosBrancos. Para outro número, procure o candidato cadastrado. Ao encontrar, aumente o voto da posição correspondente e contaVotosValidos. Quando nenhum candidato for encontrado, aumente somente contaVotosNulos.

13.4. Cenário obrigatório de conferência

  1. Crie uma urna com capacidade para 2 candidatos.
  2. Cadastre Ana com número 10 e Bia com número 20.
  3. Tente cadastrar um terceiro candidato. Confirme que os dois cadastros anteriores permanecem os únicos armazenados.
  4. Confira a lista retornada por GetNumCandidatos. Ela deve conter, nesta ordem, 10 e 20.
  5. Confira GetCandidato(10), GetCandidato(-1) e GetCandidato(99). Os retornos devem ser, respectivamente, Ana, VOTO EM BRANCO e VOTO NULO.
  6. Registre dois votos para 10, um voto para 20, um voto para -1 e um voto para 99.
  7. Confira GetVotos(10), GetVotos(20), GetVotos(-1) e GetVotos(99). Os retornos devem ser, respectivamente, 2, 1, 1 e 1.

13.5. Critérios de conclusão

  • Todos os campos indicados no diagrama são privados e possuem os tipos mostrados.
  • Os métodos públicos possuem os nomes, parâmetros e retornos mostrados no diagrama.
  • Os arrays não são acessados nem retornados diretamente pelo programa.
  • O cadastro não ultrapassa a capacidade definida no construtor.
  • Voto branco, voto válido e voto nulo atualizam somente os contadores ou posições previstos para cada caso.
  • O cenário obrigatório produz todos os retornos esperados.
